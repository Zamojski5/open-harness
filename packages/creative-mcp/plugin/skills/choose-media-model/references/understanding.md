# Watch and listen to a clip

Use only when the job needs evidence beyond the local technical checks. Everything below the table's last row runs locally and costs nothing.

| Question                                                                         | Approach                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout, text, framing, a still                                                   | `media_frames {path, frames: 8–16}` contact sheet, or single frames: `ffmpeg -ss T -i clip.mp4 -frames:v 1 review/f-T.png`. Choose times before the end of the real duration (`media_inspect`).                                                                                                                                   |
| Loudness, black, silence, freezes, duration, cuts, flashes, soft/upscaled source | `media_review {path, platform?, expected_duration?}`. It measures the file; it does not watch motion or listen to the content.                                                                                                                                                                                                    |
| 1–2 frame pops, flicker                                                          | `media_flicker {path, sensitivity?}`.                                                                                                                                                                                                                                                                                             |
| What was said                                                                    | No transcription tool is wired in. Use the user's script, or a Scribe v2 run (`fal-ai/elevenlabs/speech-to-text/scribe-v2`) only after `media_model_schema` shows `media_generate` can call it; otherwise listen-check is not possible, say so. Words on a page say nothing about delivery, score, effects or whether lips match. |
| Small, fast detail (mouths during speech, fingers, tiny lettering)               | A dense local strip around the moment, every 0.04 s across ±0.5 s, cropped to the face or hands: `ffmpeg -ss 2.7 -t 1 -i clip.mp4 -vf "crop=W:H:X:Y,fps=25,scale=320:-2,tile=5x5" -frames:v 1 review/lips-3.2.png`.                                                                                                               |
| Motion over time, A/V sync, how music/voice/SFX sound                            | Hosted video+audio understanding (below) — **not available in Open Herness**.                                                                                                                                                                                                                                                     |

For an audio-only file you still want to inspect visually (levels over time), make a temporary MP4 with a static picture and the original audio: `ffmpeg -loop 1 -i still.png -i audio.wav -shortest -c:v libx264 -tune stillimage -c:a aac tmp/audio-check.mp4`, or plot `showwavespic`.

## Hosted understanding (gap)

A hosted route sends the clip to fal's `openrouter/router/video` with `google/gemini-3.8-flash` as the downstream model (`video_urls`, a question prompt, `reasoning: true`, `max_tokens` ~1500) and reads back a description with times plus how many frames it saw (about one per second). It accepted a 50 MB file; a 115 MB upload hit a 20 MB expanded-request limit inside the router.

`media_generate` has no kind for text answers, so this route is unsupported here. Only if `media_model_schema {model: "openrouter/router/video"}` resolves and a `media_generate` call returns the text should you try it, and then treat the answer as a claim to verify against frames, never as proof. Otherwise rely on the local rows above and tell the user what could not be checked (for example sync or music quality).
